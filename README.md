# DITIB Worms

Website for DITIB Worms, built with [Next.js](https://nextjs.org/) (Pages Router) and designed in
[Plasmic](https://www.plasmic.app/). Page and component layouts are authored visually in Plasmic
Studio and pulled into this repository, so content and design changes do not require a code change.

## Tech stack

| Piece | Choice |
| --- | --- |
| Framework | Next.js 14 (Pages Router) |
| Language | TypeScript (strict) |
| UI source | Plasmic — project **Agency Website** |
| Styling | CSS Modules generated by Plasmic |
| Components | `@plasmicpkgs/react-aria` for accessible form primitives |
| Linting | ESLint via `next/core-web-vitals` + `next/typescript` |

## Repository state

This repository currently tracks **configuration only**. The generated application source —
`pages/`, `components/`, `public/`, and `styles/` — was removed in a previous cleanup and is
recreated by syncing from Plasmic (see [Syncing from Plasmic](#syncing-from-plasmic)). Run a sync
before `npm run dev` or `npm run build`, otherwise Next.js has no pages to serve.

## Getting started

Requirements: Node.js 18 or newer and npm.

```bash
git clone https://github.com/Talha199/Ditib.git
cd Ditib
npm install
npx plasmic sync          # generate pages/ and components/ from Plasmic
npm run dev
```

The dev server runs at [http://localhost:3000](http://localhost:3000).

### Scripts

| Command | What it does |

| `npm run dev` | Start the development server with hot reload |
| `npm run build` | Create a production build |

## How the Plasmic integration works

The project uses both Plasmic integration modes, which is why there are two config files:

- **Codegen** (`plasmic.json`) — the Plasmic CLI writes real React components into `components/`
  under the `plasmic/agency_website/` directory, plus thin, editable wrappers next to them. Files
  inside `components/plasmic/` are overwritten on every sync; the wrappers are yours to edit.
- **Loader** (`plasmic-init.ts`) — `@plasmicapp/loader-nextjs` fetches published pages at build
  time. The catch-all route `pages/[[...catchall]].tsx` renders any Plasmic page that has no
  hand-written route, using `getStaticPaths`/`getStaticProps` with 60-second incremental
  regeneration.

`plasmic-init.ts` also exposes `preview`, which defaults to `false` so builds use the last
*published* Plasmic version. Set it to `true` locally to render unpublished drafts — it is slower
and should not be committed as `true`.

### Syncing from Plasmic

```bash
npx plasmic sync
```

This reads `plasmic.json`, pulls the latest published version of the **Agency Website** project,
and regenerates the component tree. Commit the resulting files. Never edit anything under
`components/plasmic/` by hand — the next sync will discard it.

### App host

To use custom code components inside Plasmic Studio, point the project's app host at
`/plasmic-host` (`http://localhost:3000/plasmic-host` in development). Register components in
`plasmic-init.ts` with `PLASMIC.registerComponent(...)`. See the
[app hosting docs](https://docs.plasmic.app/learn/app-hosting/).

## Project structure

```
.
├── plasmic-init.ts     # Loader setup: project IDs, tokens, preview flag
├── plasmic.json        # Codegen config: what the CLI writes and where
├── plasmic.lock        # Checksums of synced files — do not edit by hand
├── next.config.mjs     # Next.js config (React strict mode)
├── tsconfig.json       # TypeScript config, "@/*" path alias to the repo root
└── .eslintrc.json      # ESLint config
```

After a sync, `components/` (generated UI), `pages/` (routes), `public/` (images), and `styles/`
(global CSS) appear alongside these.

## Configuration notes

The Plasmic project IDs and API tokens in `plasmic-init.ts` and `plasmic.json` are checked into the
repository, which is the default Plasmic setup — the loader token is a read-only key meant to ship
to the client. If you fork this project, replace them with your own project's values.

## Deployment

Any host that supports Next.js works; the build is a standard `npm run build` / `npm start`. Because
pages are statically generated from Plasmic content, publishing a change in Plasmic Studio requires
a rebuild (or a wait for incremental regeneration) for it to appear on the deployed site.

A `repository_dispatch` GitHub Actions workflow previously handled sync-and-deploy on Plasmic
publish; it is no longer present in this repository. To restore automated publishing, add a workflow
using [`plasmicapp/plasmic-action`](https://github.com/plasmicapp/plasmic-action).
